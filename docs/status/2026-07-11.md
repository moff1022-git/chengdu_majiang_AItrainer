| # | 现象 | 根因（终态） | 最终策略 | 曾尝试后回退 |

| A | 确认后像「没开局」 | 布局飞到竖屏副屏负 Y；主窗不可见 | 主线程 pin + 当前屏 plan；开局路径加固 | — |
| B | `players_spec` UnboundLocalError | `work()` 内赋值使名变局部 | `effective_spec` | — |
| C | 主窗/座位分离、位置乱 | 光标在副屏；SDL 定位不稳 | 开局 `detect_screen()`；座位 Tk CLI + `set_geometry` | 强拽主屏 / 仅跟主窗 |
| D | 启动数秒 SEGV | `_sdl2.Window` 属性读写破坏 event/draw | **禁用 _sdl2**；仅 env + `set_mode` | 写 position/size |
| E | 座位加载完主程序崩 | 后台线程 `set_mode` | `reassert` **禁止碰主窗** | `display.quit` 重开 |
| F | 玩家窗 Y 低约一整屏 | Tk `+x-y` = 距底边，非 y 为负 | `format_tk_geometry` → `+x+-y`；`--y=-N`；漂移校正 | NSScreen+sharedApplication（破坏 Tk） |

**原则沉淀**：在 macOS + pygame 2.6 上，**显示/主窗 API 只能主线程调用**；**不要碰 `_sdl2` 窗口对象**；座位子进程用 **Tk 几何字符串** 定位。

## 3. 最终行为说明（产品视角）

### 3.1 开局

1. 封面点「开始」（普通绿钮）  
2. 主线程：检测当前屏 → `WindowPlan` → pin 主窗  
3. 后台：串行启动 S0–S3 座位窗 → 发 `ready_request`  
4. 四窗确认后：组 `players`（可含座位 AI 覆盖）→ 引擎 `run`  
5. 错误：留在牌桌文案，不静默回封面  

### 3.2 窗口

| 窗口 | 定位方式 |
|------|----------|
| 主程序 | `SDL_VIDEO_WINDOW_POS` + 主线程 `set_mode` |
| 座位窗 | 启动 CLI `--x/--y/--width/--height`；运行中 `set_geometry` |

### 3.3 座位设置

- 标题下常显：**自动开始**、**AI 策略（规则/随机，下局生效）**  
- 可选「更多…」展开说明

## 6. 已知限制 / 技术债

1. **macOS 多显示器**：SDL 对窗口位置不一定总生效，主窗与座位偶发不完全同屏  
2. **竖屏副屏 + 负 Y**：已修 Tk 几何解析；极端排列仍可能需手拖  
3. **未单独开 F00xx 规格**：本日以 bugfix 为主，权威在 changelog + 本复盘  
4. **过程条目勿混用**：changelog 中曾出现「启用 _sdl2」类过程描述，**以本节「最终状态」为准**
