# F0070 Task 19 决策框架能力升级

- 状态：Review
- 日期：2026-08-06
- 依赖：Task 19完整基线、F0057、F0066、F0068、v0.3.2
- 任务方向：B（升级决策框架，不搜索人格参数）

## 1. 背景与目标

v0.3.2证明现有Task 19框架下的Nonhuman参数可稳定超过Expert，但公开trace也显示计划生命周期、多步价值、公开进张质量、对手风险和碰杠后状态评估仍有结构性上限。本任务以v0.3.2 Nonhuman为强制防回退基线，通过彼此隔离的工作包升级HumanlikeV2Player的决策能力。

目标是改善不可由现有7+12参数表达的决策能力，而不是重新搜索Nonhuman参数。

## 2. 架构与安全原则

- Engine继续是合法动作、定缺、胡牌、碰杠、血战退出和计分的唯一权威。
- HumanlikeV2Player只消费`PlayerView`公开投影，不访问对手暗手、未公开牌墙、未来摸牌或复盘oracle。
- 新评分、计划或风险特征必须进入参数/RP注册、trace和审计白名单。
- 任何工作包先完成文档Approved，再修改业务代码。
- F0069参数搜索与本任务完全分开；每个框架A/B使用冻结的v0.3.2参数。

## 3. 范围

### In Scope

1. 计划生命周期与惯性实际生效。
2. 有界、无上帝视角的多步弃牌价值。
3. 独立公开进张质量特征与F0068单参数因果A/B。
4. 只基于公开信息的对手听牌/危险/多人支付风险。
5. 碰杠后状态搜索与方案连续性。
6. 规则、信息边界、场景、小样本、独立数据集和盲测的分阶段门禁。

### Out of Scope

- 不恢复已经失败的F0050–F0053公式或用其换名版绕过证据。
- 不同时开发多个工作包后用一次总分宣称因果。
- 不修改成都麻将规则，不将Player预测升格为Engine事实。
- 不在本规格下修改13种人格的7+12默认值。

## 4. 工作包

### WP-B1 计划生命周期

目标：解决trace中约98.16%计划重启率导致的“计划存在但无法影响决策”风险。

设计要求：

- 明确计划创建、继承、命中、修订、失效和重启的状态机。
- 仅当手牌结构、定缺约束、公开信息或法定动作使原计划失效时重启。
- `plan_persistence`必须通过可审计的排序项实际影响候选，不得只出现在快照。
- trace必须记录`plan_id`、age、restart_reason、inertial_match、ranking_delta和选中结果。

门禁：重启率下降不能以降低合法性、定缺优先或HU mandatory一致性为代价；必须同时提高计划年龄可解释性和惯性命中率。

### WP-B2 多步弃牌价值

目标：评估“当前动作 → 所有公开可能摸牌类别 → 下一步最佳弃牌”，而不只比较当前一步分数。

设计要求：

- 只枚举根据公开剩余计数可能出现的牌面类别，不读真实未来牌墙顺序。
- 使用确定性、有界beam/depth、备忘录和预算截断。
- 区分一步改善、两步改善、牌型价值和风险暴露；禁止重复计分。
- trace记录扩展节点数、截断原因、预期价值和与一步排名的差异。

门禁：信息边界测试0违规；同一PlayerView确定性一致；P95响应和内存不超过预注册预算。

### WP-B3 公开进张质量与F0068

目标：将`ukeire_public_count`从混合公式中分离为独立、可追踪、可归零的倍率，并执行F0068预注册A/B。

设计要求：

- 明确“一步公开进张数”、“进张后最佳向听”、“两步广义有效进张”和重复牌面剩余数的语义。
- 独立倍率加入参数注册、配置兼容、人格快照和audit trace。
- 先通过等价性测试证明倍率`1.00`与当前行为相同，再运行`1.00 vs 0.00`。
- 严格使用F0068已冻结的数据、终点和判定规则。

### WP-B4 对手公开风险模型

目标：基于弃牌河、副露、定缺、已胡/未胡状态和公开牌数，估计对手听牌可能性、牌面危险和血战多人支付风险。

设计要求：

- 先定义`PlayerView`输入白名单和禁止字段测试。
- 风险输出是概率/相对分数，不是Engine事实。
- 校准、区分度和决策收益分开验证；不仅以总分评价模型。
- 多对手支付风险需考虑已胡退出和剩余活跃座位。

### WP-B5 碰杠后状态搜索

目标：对PONG/MING_GANG/AN_GANG/BU_GANG之后的手牌结构、定缺剩余、下一弃牌和方案连续性做真实状态评估。

设计要求：

- 候选必须使用Engine授权的合法动作投影，不在Player内复制规则。
- 显式复现并解释F0050–F0053旧模型失败的原因，新机制必须用反例测试证明不重复旧错误。
- 碰后首弃、杠后摸牌、方案重启、花猪和HU mandatory均有专项trace。
- 只有独立A/B证明收益后才能进入后续工作包。

### WP-B6 统一trace与审计门禁

- 一次性采集计划重启、计划年龄、惯性命中、排序变化、HU mandatory、公开进张、多步节点、风险和碰杠后状态。
- 字段覆盖率、类型、值域、来源和hash链加入自动门禁，避免再因采集不完整重跑长测。
- trace逻辑不得改变决策行为；关闭trace时的行为结果必须一致。

## 5. 分阶段门禁

每个WP独立经过以下阶段，未通过不得进入下一阶段：

1. **规格门禁**：独立功能规格Approved，输入边界、语义、trace和回滚完整。
2. **规则/信息边界**：Engine权威、合法动作、禁止字段和HU mandatory测试通过。
3. **单元/场景**：正例、反例、边界、人格差异和trace完整性通过。
4. **100局smoke**：固定牌局、100%成功、结果可复现、完整trace。
5. **1000局选择测试**：只用于淘汰和检查机制，不作最终晋级依据。
6. **独立多数据集**：至少两个新SHA，验证座位和阵容泛化。
7. **最终盲测**：预注册主终点、样本量和护栏；只读取一次。
8. **防回退**：v0.3.2 Nonhuman门禁必须PASS，否则工作包不晋级。
