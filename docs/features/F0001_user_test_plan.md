## 0. 测试前准备

### 0.1 环境

| 项 | 要求 |
|----|------|
| OS | Windows（当前主力）；有条件可再测一台 1080p 与一台 ≥2K |
| Python | 3.11+ |
| 依赖 | 项目根执行 `pip install -r requirements.txt` |
| 显示 | 单主屏；记录分辨率（设置 → 系统 → 显示） |
| 工作目录 | 仓库根：`chengdu_majiang_AItrainer` |

### 0.2 建议测试矩阵（分辨率）

| 场景 | 分辨率 | 目的 |
|------|--------|------|
| A | 1920×1080 | 最常见 1080p |
| B | 2560×1440 或更高 | 2K 上限 / 更大桌面 |
| C（可选） | 1366×768 或笔记本小屏 | 自动缩小是否溢出 |

无法切换分辨率时：至少完成 **A**，并在结果中注明实际分辨率。

### 0.3 自动化冒烟（开测前 1 分钟）

**必须在仓库根目录**执行（含 `main.py` / `display/` 的那一层），不要 `cd tests` 后再跑：

```bash
cd chengdu_majiang_AItrainer
pytest tests/test_window_geometry.py tests/test_asset_manager.py -q
```

期望：全部 **passed**（不应出现 collection ERROR）。  
若仍报 `No module named 'display'`：确认根目录有 `pytest.ini`（`pythonpath = .`）与 `tests/conftest.py`。  
失败则**不要**继续 UI 人工测，先修。

### 0.4 记录表（建议复制到笔记）

| 用例 ID | 结果 | 备注（分辨率/截图） |
|---------|------|---------------------|
| U01 … | 通过 / 失败 / 阻塞 | |

判定：**通过** = 符合期望；**失败** = 行为错误；**阻塞** = 无法执行（崩溃/无窗）。

## 2. L1 — 主程序（观战 GUI）

### 启动命令

```bash
python main.py play --players rule_ai,rule_ai,rule_ai,rule_ai --theme green
```

或：

```bash
python main.py gui --theme green
```

（`gui` 先进大厅；`play` 无 human 时自动开局观战。）

---

### U01 主窗初始居中（F0001 G2）

| 步骤 | 操作 |
|------|------|
| 1 | 关闭其它占满屏窗口，执行启动命令 |
| 2 | 观察主窗口出现位置 |

| 期望 | 否决条件 |
|------|----------|
| 窗口大致在**屏幕中部**（允许几像素误差） | 贴死左上角/完全跑出可视区 |

---

### U02 初始尺寸合理且未超出 2K 工作区（G1/G5）

| 步骤 | 操作 |
|------|------|
| 1 | 目视主窗默认大小（设计约 1280×720，小屏会更小） |
| 2 | 确认窗口**完整落在屏幕内**，无被任务栏严重裁切 |

| 期望 | 否决条件 |
|------|----------|
| 整窗可见；大屏上不会按 4K 铺满整个超大桌面作为「工作区外乱摆」 | 窗口超出屏幕一半以上 / 无法看到标题栏 |

---

### U03 主窗可动态缩放（G4）

| 步骤 | 操作 |
|------|------|
| 1 | 拖拽窗口**右下角/边缘**放大 |
| 2 | 再缩小到接近最小 |
| 3 | 观察大厅或牌桌背景、按钮、文字是否仍可用 |

| 期望 | 否决条件 |
|------|----------|
| 可缩放；放大后背景铺满；控件仍可点；无持续花屏/崩溃 | 无法缩放；缩放后黑屏且无法恢复；必现崩溃 |

补充：大厅有提示「drag edge to resize」属正常。

---

### U04 大厅交互（主题 / 开始）

| 步骤 | 操作 |
|------|------|
| 1 | `python main.py gui` |
| 2 | 按 **T** 或点击主题区域，切换 green/blue |
| 3 | 按 **Enter** 或点 Start 进入对局 |

| 期望 | 否决条件 |
|------|----------|
| 主题资源切换明显；能进入 table 场景 | 无法开局；主题切换崩溃 |

---

### U05 观战桌面与 HUD

| 步骤 | 操作 |
|------|------|
| 1 | AI 自对弈进行中 |
| 2 | 按 **H** 开关 HUD；**1–4** 切换 focus 座位 |
| 3 | **+ / -** 调步进速度；**→** 可尝试加速一步（若实现） |
| 4 | 等待进入 Result（或快速打完） |

| 期望 | 否决条件 |
|------|----------|
| 四家手牌/分数/剩余墙可见；HUD 可关可开；终局到 Result | 牌桌空白长时间不动且无错误信息（可先等 30s） |

---

### U06 结算与返回

| 步骤 | 操作 |
|------|------|
| 1 | Result 界面 |
| 2 | **R / Enter** 再来一局，或 **L** / 点 Lobby 回大厅 |
| 3 | **Esc** 从大厅退出 |

| 期望 | 否决条件 |
|------|----------|
| 场景切换正常；可退出 | 卡死在 Result |

---

### U07 缩放后场景切换（回归布局）

| 步骤 | 操作 |
|------|------|
| 1 | 在大厅把窗口拉到很大（如接近全屏） |
| 2 | Start → 对局 → 等 Result 或 Esc 回大厅 |
| 3 | 再缩回中等大小，点 Start |

| 期望 | 否决条件 |
|------|----------|
| 各场景按当前窗口重排，按钮可点 | 热区错位严重（点 Start 无反应且位置明显偏） |

## 3. L2 — Human 玩家窗口

> 注意：含 `human` 时主程序走 **headless 引擎**，**不会**同时开主 GUI；屏幕上主要是 **Human 子进程窗口**（1 个 human → 1 窗）。  
> 「四向」在 **单 human** 时只验证**该座位**对应方位；完整四窗需四个人工位（一般不做）。

### 启动命令（推荐：完整双窗 UI）

```bash
python main.py human --theme green
```

等价：

```bash
python main.py play --players human,rule_ai,rule_ai,rule_ai --theme green
```

默认 human 在 **座位 0 → 玩家窗偏屏幕下方（bottom）**；**主程序窗居中**观战。  
仅玩家窗、无主界面：加 `--headless`（不推荐上手玩）。

---

### U10 主程序 + Human 窗同时出现

| 步骤 | 操作 |
|------|------|
| 1 | 执行 human 命令 |
| 2 | 等待 **两个** 窗口：主程序标题含「主程序」；玩家窗含 Human Seat |
| 3 | 玩家窗进入换三张/定缺；主窗显示牌桌状态 |

| 期望 | 否决条件 |
|------|----------|
| 双窗均弹出；主窗可刷新状态；玩家窗可操作 | 仅有一窗；控制台崩溃；hello 超时 |

---

### U11 座位 0 初始方位（G3）

| 步骤 | 操作 |
|------|------|
| 1 | 单屏、无其它大窗遮挡 |
| 2 | 观察 human 窗相对屏幕中心的位置 |

| 期望 | 否决条件 |
|------|----------|
| **座位 0**：窗口中心大致在屏幕**下半区**（主窗虚拟占位中心之下） | 固定钉在左上角 (0,0) 且与「下方」明显不符 |

说明：无主 GUI 时，位置仍按「虚拟主窗居中」计算，故玩家窗在下方偏中，**不是**贴屏幕最底边缘也算合理。

---

### U12 Human 窗可缩放（G4）

| 步骤 | 操作 |
|------|------|
| 1 | 拖拽玩家窗边缘放大/缩小 |
| 2 | 观察手牌是否仍横排可见、按钮是否仍在底部区域 |

| 期望 | 否决条件 |
|------|----------|
| 可缩放；手牌/按钮仍大致可用 | 缩放崩溃；牌完全点不到 |

---

### U13 换三张

| 步骤 | 操作 |
|------|------|
| 1 | phase=exchange |
| 2 | 点击 3 张**同花色**手牌（高亮） |
| 3 | 点 confirm / Enter |

| 期望 | 否决条件 |
|------|----------|
| 进入定缺或等待；非法三张无法确认（或提示后不推进） | 选牌无反馈；确认后卡死 |

---

### U14 定缺

| 步骤 | 操作 |
|------|------|
| 1 | 点击 wan / tong / tiao 按钮之一 |

| 期望 | 否决条件 |
|------|----------|
| 进入行牌；显示 Waiting / 轮到你 |

---

### U15 行牌：弃牌

| 步骤 | 操作 |
|------|------|
| 1 | 轮到 discard 时点选手牌 |
| 2 | confirm 或 Enter |

| 期望 | 否决条件 |
|------|----------|
| 出牌成功；轮转继续 | 合法弃牌被拒且无法操作 |

---

### U16 行牌：碰/杠/胡/过（机会出现时）

| 步骤 | 操作 |
|------|------|
| 1 | 出现对应按钮时点一次 |
| 2 | 无意图时点 pass |

| 期望 | 否决条件 |
|------|----------|
| 动作被接受或合法拒绝后仍可继续 | 一点就崩 |

若整局未出现碰杠胡：记 **跳过（环境未触发）**，不判失败。

---

### U17 打完一局

| 步骤 | 操作 |
|------|------|
| 1 | 尽量打到终局（可较慢；rule_ai 对手） |
| 2 | 观察控制台打印 finished / scores；子进程是否正常结束 |

| 期望 | 否决条件 |
|------|----------|
| 有终局结果；进程可退出 | 无限卡在 Waiting 且引擎无输出超过 5 分钟 |

可选加速：仅验证开局三相（换三张+定缺+首次弃牌）即通过 U13–U15，U17 标「部分」。

### U18 不同座位方位（可选，加强 G3）

分别启动（每次只测一个）：

```bash
# 座位 0 → 下
python main.py play --players human,rule_ai,rule_ai,rule_ai

# 座位 1 → 右（human 在第二位）
python main.py play --players rule_ai,human,rule_ai,rule_ai

# 座位 2 → 上
python main.py play --players rule_ai,rule_ai,human,rule_ai

# 座位 3 → 左
python main.py play --players rule_ai,rule_ai,rule_ai,human
```

| 座位 | 期望方位（相对屏幕中心） |
|------|--------------------------|
| 0 | 偏下 |
| 1 | 偏右 |
| 2 | 偏上 |
| 3 | 偏左 |

每例只需确认窗口弹出位置，**不必打完一局**（开局后可关窗结束进程）。

## 5. 已知限制（测到勿当 bug）

| 现象 | 说明 |
|------|------|
| human 模式无主 GUI | 设计如此（引擎 headless + 子进程窗） |
| 2K 只约束**初始**布局 | 用户可手动拖到大于 2K |
| 多显示器 | 仅按主屏估算；副屏行为不保证 |
| SDL 窗口位置 | 个别显卡/DPI 下可能有数像素偏差 |
| AI 观战速度 | 依赖 step-ms，可调 +/- |
