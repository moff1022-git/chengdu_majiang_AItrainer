## 0. 结论摘要（先读）

| # | 结论 |
|---|------|
| 1 | **主流线上血战/川麻对战**集中在腾讯系（欢乐麻将）、竞技世界（JJ 麻将）、微信小游戏/独立川麻 App 合集；**几乎无对个人开发者开放的「官方 Bot API」**。 |
| 2 | 将本项目 AI（`rule_ai` / Humanlike v2）**直接接入商业平台自动打牌**，若走协议逆向 / 模拟点击 / 内存注入，**高度可能违反用户协议与相关法规**，本仓库**不采纳为实现目标**。 |
| 3 | **技术上可行且合规的路径**优先：① **自建/内嵌联网对战**（本引擎权威）→ ② **官方/商务合作 AI 接口**（B2B）→ ③ **教练/旁路 HUD**（只读提示，不代操作）→ ④ 仅作架构参考的 **MJAI 类标准协议**（日麻规则不可照搬）。 |
| 4 | 本项目已具备接入外壳核心：**引擎权威、`BasePlayer.decide`、座位 NDJSON、Gym env、Humanlike 决策审计**；缺 **网络对战层 + OnlineAdapter + 合规策略**。 |
| 5 | 建议路线：**DecisionService 服务化 → 自建好友房自动 AI →（可选）商务合作**；商业客户端外挂永不进入实现队列。 |

## 1. 背景与目标

### 1.1 背景

本仓库是 **成都麻将 · 血战到底** 本地权威引擎 + 可插拔 AI/人类 + UI + 训练与 Humanlike v2 策略。`PLAN.md` 首版 **非目标**含网络多人实时对战服务器。用户要求评估：如何将现有 AI **接到线上主流平台并自动玩牌**。

### 1.2 文档目标

| ID | 目标 |
|----|------|
| G1 | 梳理当前**线上主流血战到底/川麻对战**形态与代表产品 |
| G2 | 分析 AI 自动接入的**技术路径、成本、风险** |
| G3 | 给出与本项目架构对齐的**分层方案与阶段路线** |
| G4 | 明确 **In / Out of Scope** 与合规边界 |

### 1.3 非目标

- 不提供任何商业 App 的逆向协议、破解、注入、批量脚本 PoC  
- 不承诺「挂机打金」或绕过反作弊  
- 本轮**不写业务代码**（待 `Approved` 且选定路径后再开实现 F/M）

## 2. 线上平台调研（公开信息）

> 棋牌市场迭代快；以下为公开应用商店/官网/百科/技术文章归纳，**非**精确市场份额。

### 2.1 产品形态

| 类型 | 特征 | 与血战到底 |
|------|------|------------|
| A. 国民级合集 App | 大 DAU、3D 牌桌、多地方玩法、真人对战 | 常含四川**血流/血战** |
| B. 川麻垂直 / 小游戏 | 微信小游戏、独立 App、方言 | 更贴近四川本地规则 |
| C. 竞技赛事向 | 赛制、奖金/积分 | 如 JJ 麻将赛事 |
| D. 单机 / 弱联网 | 本地 AI | 非主流「线上对战」 |
| E. 国际/日麻平台 | 天凤、雀魂 | **规则非川麻**；AI 协议生态可作架构参考 |

### 2.2 代表平台

| 平台 / 产品 | 运营（公开） | 模式要点 | 对第三方 AI 接入（公开层） |
|-------------|--------------|----------|----------------------------|
| **欢乐麻将全集** | 腾讯 | 真人对战；四川血流/血战、打缺门、刮风下雨等 | **无公开 Bot API**；强反作弊预期 |
| **JJ 麻将** | 竞技世界 | 含四川血战等地方玩法；赛事 | 同上 |
| **四川麻将血战到底（微信小游戏等）** | 多家 | 轻量社交房 | 闭源加密常见 |
| **人人麻将** 等 | 独立发行 | 血流/血战/红中等 | 闭源 |
| **禅游等渠道川麻 App** | 禅游等 | 定缺、一胡到底等 | 闭源 |
| **蜀山四川麻将** 等 | 区域棋牌 | 好友房、血流红中 | 闭源 |
| **兜来玩麻将**（快手案例） | 快手 | 血战/血流等；**平台自研 AI** 填匹配/代打 | **内部能力**，非第三方 SDK |
| **天凤 / 雀魂** | 日麻生态 | Suphx、Mortal、MahjongCopilot | 有研究/第三方协议；**规则不适配本引擎** |

检索结论：**无面向个人开发者的「成都血战官方实时出牌 Bot SDK」**。

### 2.3 行业技术共性

```text
客户端 → 加密长连接/WS → 网关+反作弊 → 房间/匹配/结算 → 服务端权威状态
```

- 服务端权威（与本项目 `engine/` 角色类似，但状态在对方）  
- 私有协议与动作编码 ≠ 本仓库 `Action` / `GameState`  
- 反作弊：时序、多开、脚本特征、设备指纹  
- 同名「血战」在换三张、封顶、查叫、杠分上可能与本引擎配置有差异

## 4. 方案矩阵

### 4.1 统一抽象

```text
 Policy (rule_ai / humanlike / 人类)
        ▲ ActionRequest / Decision
 OnlineBridge / Adapter
        ▲
 SelfHostRoom | Official API | （禁止）逆向客户端
```

**决策层不依赖 UI；Adapter 负责观测翻译与动作回写。**

### 4.2 方案 A — 自建线上对战（**推荐主路径**）

| 项 | 内容 |
|----|------|
| 思路 | 房间服 + 客户端；权威=`engine`；席位接 AI/人类 |
| 自动玩牌 | 全 AI 或 1 人 3 AI，天然合规 |
| 优点 | 规则一致、可复现 `game_id`、可产训练日志 |
| 缺点 | 无现成 DAU |
| 粗估 | 好友房 MVP 数周；公网匹配数月 |

子路径：**A1 局域网/好友房** → **A2 公网匹配**。

### 4.3 方案 B — 官方/商务合作

| 项 | 内容 |
|----|------|
| 思路 | 厂商提供匹配填充/掉线代打 API；本侧只跑 Policy 服务 |
| 先例 | 快手等业务内多玩法麻将 AI（公开分享，**非**对外开放） |
| 优点 | 合规商用 |
| 缺点 | 商务门槛 |

建议接口形态：`observation + legal_actions → action`（规则集 ID 必填）。

### 4.4 方案 C — 教练 / 旁路 HUD

| 项 | 内容 |
|----|------|
| 思路 | **不代点击**；根据可见信息推荐（对齐 F0011） |
| 对照 | 雀魂 MahjongCopilot 等形态（**存在 ToS 风险**，仅架构参考） |
| 定位 | 教学产品；与外挂切割 |

### 4.5 方案 D/E — 逆向协议 / RPA 点击

| 项 | 内容 |
|----|------|
| 风险 | 违约、封号、法律与伦理 |
| 本项目 | **Out of Scope；禁止实现与细节指导** |

### 4.6 方案 F — MJAI 类标准协议（架构借鉴）

- 可借鉴：平台与 AI 进程解耦的事件流  
- 不可照搬：立直规则与模型  
- 建议自建 **CMJ-AI Wire**（从 `protocols.wire` 演进）

## 6. 分阶段路线

| 阶段 | 内容 | 产出 |
|------|------|------|
| 0 | 本文 + 用户选定 A/B/C | Draft → Approved |
| 1 | **DecisionService**（HTTP/进程内） | `ActionRequest`→`Decision`；rule_ai + humanlike |
| 2a | **自建好友房 MVP** | WS 房间 + 全 AI 自动局 |
| 2b | 教练 HUD（可选） | 推荐不代打 |
| 3 | 商务 API Adapter（有合同再开） | 官方 schema 映射 |
| ∞ | 未授权商业端 Bot | **永不做** |

### 6.1 DecisionService API 草案

```json
// Request
{
  "protocol": 1,
  "ruleset_id": "chengdu_blood_v1",
  "seat": 0,
  "phase": "discard",
  "view": {},
  "legal_actions": [{ "type": "discard", "tile": "3w" }],
  "policy": "rule_ai"
}

// Response
{
  "action": { "type": "discard", "tile": "3w" },
  "reason": "rule_ai:shanten",
  "think_ms": 8
}
```

### 6.2 自建房事件（草案）

`state_snapshot` / `action_request` / `action_submit` / `reject` / `game_end`  
可与座位 `PROTOCOL_VERSION` 分线演进。

### 6.3 延迟预算（建议）

| 环节 | 目标 |
|------|------|
| rule_ai decide | p99 < 50ms |
| humanlike | 按认知参数 think_ms |
| 超时 | 安全动作：过 / 最短向听出牌 |

## 7. 合规与风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 商业 App 外挂 / ToS | **高** | 禁止 D/E |
| 灰色打金 | **高** | 产品定位训练/教学/自建娱乐 |
| 规则不一致 | 中 | 差异矩阵 + 牌谱回归 |
| 用户误认为官方挂 | 中 | 免责声明 |

**法律提示（非律师意见）：** 未经授权对他人运营的网络游戏进行自动化操作或破坏技术措施，可能构成违约及不正当竞争等；自建/科研环境不豁免对第三方商业服务的侵权。
