# F0070 主代理总控与自动子代理编排契约

- 状态：Approved（用户于2026-08-06明确要求两个任务线均采用主代理总控、自动生成子代理、自动授权边界内全自动运行）
- 日期：2026-08-06
- 适用范围：`feature/f0070-v0.4.0` / `worktrees/f0070-v0.4.0/`
- 依赖：F0070主规格Approved、ADR-0002、`AGENTS.md`、`docs/DEVELOPMENT.md`
- 现有机制：`tools/task19_agent_runtime.py`、`tools/task19_monitor.py`

## 1. 目标

F0070全部工作包采用一个主代理总控。主代理读取仓库内权威状态，自动拆分有边界的任务，按依赖与并发上限生成子代理，验收其产出，并在CLI重启后幂等续跑。自动化不得改变Docs-First门禁、平台权限边界、F0069/F0070隔离或统计盲测约束。

“全自动运行”仅指：在用户已经批准的规格和本契约授权范围内，主代理不再逐步等待普通执行确认。它不表示可以绕过操作系统、Codex平台、Git托管服务或真正人工门禁。

## 2. 权威来源与角色

权威读取顺序：

1. `docs/status/LATEST.md`；
2. `docs/status/streams/F0070_V040_LATEST.md`；
3. 当前WP规格和依赖规格；
4. `docs/changelog.md`；
5. 编排状态与证据manifest。

角色分工：

| 角色 | 职责 | 禁止 |
|---|---|---|
| 主代理 | 建图、派发、冲突仲裁、门禁判定、状态回写、最终验收 | 把未Approved规格当实现授权；亲自批准自己新增的产品语义 |
| 规格子代理 | 只修改指定`docs/`范围，提出接口、测试、验收和回滚 | 修改业务代码或把Review自行改成Approved |
| 实现子代理 | 在Approved子规格范围内编码及定向测试 | 扩scope、修改其他产品线、打开盲测结果 |
| 验证子代理 | 只读/测试验证候选，核对规格与证据 | 修复自己发现的问题后直接宣称独立通过 |
| 审计子代理 | 使用固定候选SHA或clean archive独立审计 | 与实现代理共享结论责任或静默降低门禁 |

主代理必须让实现与最终独立审计由不同子代理承担。并行任务必须路径不重叠；发生重叠时转为串行或使用独立临时工作树，禁止并发写同一文件。

## 3. 工作项与自动拆分

每个工作项至少包含：`work_id`、`wp_id`、`gate`、`dependencies`、`scope_paths`、`owner_role`、`candidate_sha`、`attempt`、`idempotency_key`、`acceptance_commands`、`evidence_paths`、`next_action`。

幂等键固定为：

```text
f0070-v040:<work_id>:<gate>:<candidate_sha-or-spec-hash>:<attempt>
```

主代理只在以下条件全部满足时自动生成子代理：

- 直接依赖均通过，且当前门禁允许下一阶段；
- 写入路径属于F0070工作树且与活动任务无冲突；
- 若为实现任务，对应WP子规格为Approved，且用户已有“实现/全自动执行”授权；
- 输入候选、验收命令、证据位置和失败回退均已确定；
- 并发槽位可用，且至少保留主代理总控能力。

建议初始DAG：`B6规格 → B6批准 → B6实现/验证/审计 → B1规格 → B1批准 → B1实现/验证/审计`；其后按F0070主规格的B3、B2、B4、B5依赖推进。B4可在无文件/实验冲突时与B2研究并行，但不得合并因果A/B。

## 4. 状态机与验收

```text
READY → DISPATCHED → RUNNING → VERIFY → AUDIT → COMPLETE
                         │          │
                         └→ REMEDIATE┘
                                  └→ HUMAN_GATE/BLOCKED
```

- 子代理完成不等于工作项完成；主代理必须核对diff、范围、测试、证据路径和候选SHA。
- 同一稳定finding最多自动修复两轮；第三次相同finding进入`HUMAN_GATE`，不得换名继续。
- 测试失败、证据hash不符、工作树脏变更来源不明、依赖漂移时不得推进。
- 每个闭环更新规格状态、stream LATEST、根LATEST和changelog；长任务还需写机器可读checkpoint。

## 5. 自动授权边界

### 5.1 可自动执行

- 只读检查、搜索、diff、状态和日志读取；
- 在当前F0070工作树内修改已授权范围文件；
- 运行规格列出的本地测试、lint、编译和可恢复实验；
- 创建、续派、终止失效的任务子代理；
- 重试瞬时失败，或针对明确finding派发最多两轮修复；
- 写入F0070数据根、临时目录和仓库内证据目录；
- 在用户明确授权全自动实现且规格Approved后，创建本地提交作为候选检查点。

### 5.2 必须请求平台/用户批准

- 沙箱外写入、GUI控制、密钥/凭据访问或平台标记为需批准的命令；
- 删除、覆盖、重置、强推、改写历史、发布Release/tag或合并分支；
- 产生费用或影响外部系统的云任务、消息、PR、CI重跑；
- 新依赖安装、网络下载、远程上传；
- 打开最终盲测、改变预注册终点/样本量、访问隔离产品线数据；
- 新产品语义、规则变化、公开接口breaking change或ADR级决策；
- 第三次相同finding、无法归因的脏工作树、证据SHA不一致。

自动授权不能替代Codex/OS权限审批。若平台要求批准，主代理直接提交最小范围审批请求；被拒后选择更安全替代方案或暂停，不得规避。

## 6. CLI重启与自动续跑

新session完成规定读序后，主代理运行：

```bash
python tools/task19_agent_runtime.py reconcile-startup --workspace worktrees/f0070-v0.4.0
```

续跑协议：

1. 忽略旧session的过期心跳，状态以工作项、Git HEAD和证据hash为准；
2. 核对工作区、分支、HEAD、F0070前缀/数据根和每个候选SHA；
3. 对`resume_queue`按依赖排序并以幂等键去重；
4. `human_gates`为空时恢复主Goal并自动续派；存在任一真正人工门禁时仅暂停受影响分支，其他无依赖工作可继续；
5. CLI关闭期间任务暂停，不安装外部daemon、launchd、计划任务或自动唤醒器。

现有runtime只生成恢复计划和记录状态，monitor只读展示；实际创建子代理、验证输出和推进门禁仍由当前session的主代理完成。后续若实现机器化F0070编排器，必须另立Approved实现规格。

## 7. 失败、回滚与隔离

- 子代理越界时立即停止该代理，保留diff供审计，不自动删除用户变更。
- 未通过候选不进入后续基线；通过独立提交、功能开关或显式反向提交回滚。
- 所有artifact使用`f0070-v040-`前缀，数据仅写`data/experiments/f0070_v040/`。
- 禁止读取/引入F0069候选、数据和参数；禁止合并回`main`。
- 最终盲测失败只记录预注册结论，不进行结果导向调参后重开同一盲测。
