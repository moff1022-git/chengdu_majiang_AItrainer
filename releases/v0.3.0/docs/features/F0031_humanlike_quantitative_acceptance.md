# F0031 人类化功能量化验收规格

| 字段 | 内容 |
|---|---|
| Feature ID | F0031 |
| 状态 | **Draft** |
| 类型 | 评测契约 / 质量门禁 |
| 依赖 | F0028、F0029、F0030 |
| 输入基线 | 两份根目录 AI 规格及 `docs/status/SPEC_IMPLEMENTATION_AUDIT_2026-07-29.md` |

## 1. 目的与判定原则

把“人类化”从机制存在、主观观感或测试通过，转换为可重复、可比较、可审计的量化结论。本规格只定义验收口径和证据要求，不修改策略算法，也不把尚无数据支持的阈值表述为既成事实。

本规格分别回答：机制和规则是否正确、参数是否产生稳定行为差异、策略强度是否合格、行为是否接近真人、局间学习是否有效。上述结论禁止合并成单一“人类化总分”。

## 2. 范围

### 2.1 In Scope

- 2/3/4 人 Humanlike v2 的决策、认知、人格、目标和审计链；
- 规则语义追踪、固定场景、批量对局、真人离线数据四类评测；
- 指标、样本、统计方法、门槛和证据产物；
- 当前实现及后续 RP-033 局间学习使用同一框架。

### 2.2 Out of Scope

- 本文档直接实现或调整 AI 算法；
- 使用未授权、未脱敏的真人数据；
- 用机制测试推断已达到真人水平；
- 为指标读取 PlayerView 之外的隐藏状态；
- 多智能体训练平台、线上匹配和竞技排位。

## 3. 验收结论分级

| 等级 | 必须通过 | 允许表述 |
|---|---|---|
| L1 机制可信 | G1、G2、G7 | 机制、规则边界和运行质量已验证 |
| L2 行为可辨识 | L1 + G3 | 参数产生稳定、可辨识的风格差异 |
| L3 策略合格 | L2 + G4 | 相对指定基准满足非劣要求 |
| L4 真人相似 | L3 + G5 | 在指定真人数据集和人群范围内达到相似度门槛 |
| L5 学习有效 | L4 + G6 | 局间学习产生统计显著且安全的效果 |

未执行门禁记为 **Not Evaluated**，不得记为 Passed。首期建议目标为 **L3**；没有合规真人数据时 L4/L5 不阻断首期，但不得宣称达成。

## 4. 统一实验协议

- 冻结应用、规则、参数、实现和脚本版本及配置哈希；保存完整 seed manifest；
- 比较策略使用配对 seed 并轮换座位；2/3/4 人和房规组合分别报告；
- 不得按结果删除 seed；崩溃、超时和无效样本均计入失败率；
- development 集调参，冻结 test 集只执行一次正式验收；
- 使用双侧 95% bootstrap CI（不少于 10,000 次），对局指标以整局重采样；
- 若主指标 CI 宽度大于门槛带宽一半，必须扩样，不能下通过结论。

| 场景 | 最低样本 |
|---|---:|
| 规则语义 | 每条规范至少 1 正例；高风险规则至少正例、反例、边界例各 1 |
| 安全批跑 | 2/3/4 人各 200 局；每种受支持核心房规组合至少 50 局 |
| 风格场景 | 每个声明参数维度至少 100 个配对决策上下文 |
| 强度评测 | 每个候选×基准×人数至少 1,000 个配对对局，座位均衡 |
| 真人相似 | 至少 10,000 个合法决策、200 局、30 名玩家；不足只作探索报告 |
| 学习效果 | 每个对手条件至少 500 个配对重复对局、20 个独立对手策略 |

## 5. G1 安全、合法与信息边界（硬门禁）

| 指标 | 通过标准 |
|---|---|
| 非法动作率 | 0 |
| PlayerView 白名单外读取或 oracle 污染决策 | 0 |
| 牌守恒/状态断言失败 | 0 |
| 崩溃或未处理异常 | 0 |
| 强制胡、过手限制、定缺等硬规则违例 | 0 |

任一项非零，整批 G1 失败，不得用平均值或置信区间豁免。

## 6. G2 规格语义覆盖与正确性（硬门禁）

建立 `规范条款 ID → 实现位置 → 测试案例 → 结果` 追踪矩阵，覆盖两份源规格全部规范性条款。

| 指标 | 通过标准 |
|---|---|
| 条款登记覆盖率 | 100% 有唯一 ID、责任模块和状态 |
| 可执行案例覆盖率 | 关键条款 100%；其余 ≥95%，未覆盖项列明理由和计划 |
| 已执行案例通过率 | 100% |
| 高风险规则矩阵 | GP-008/009/010、查叫、退税、呼叫转移、死叫、强制胡、庄家规则均有正/反/边界案例且 100% 通过 |
| 审计可解释率 | 100% 决策可追溯到候选、评分分解、认知快照、RNG 和配置版本 |

代码中存在近似逻辑不计为通过；必须由条款案例证明输入、状态转移和输出一致。

## 7. G3 风格与认知可辨识度

每个公开参数须预先指定一个主行为指标和预期方向，例如风险厌恶对应高危险出牌率下降，注意力对应纳入评估的信息比例，满意停止对应候选扫描深度下降。

| 指标 | 通过标准 |
|---|---|
| 配对场景方向一致率 | ≥80% |
| 主指标实质效应 | 配对 Cliff's delta `|δ| ≥ 0.33`，95% CI 不跨 0 |
| low/medium/high 单调性 | 被声明为有序的参数 100% 满足 |
| 风格可分类性 | 冻结测试集 macro-F1 ≥0.65，且高于置换检验 95 百分位 |
| 非目标扰动 | G1 仍全部通过 |

`δ=0.33` 和 macro-F1 `0.65` 为首版工程门槛；首次基线后可经文档审批修订，禁止验收后倒改。

## 8. G4 策略强度非劣

基准至少含 RuleAI 和冻结的上一版 Humanlike。主指标为座位轮换后的每局净分；胡牌率、花猪率、未听牌率和平均番数作诊断。

| 指标 | 通过标准 |
|---|---|
| 对 RuleAI 标准化净分差 | 95% CI 下界 > `-0.10 × 基准每局净分标准差` |
| 对上一版 Humanlike 标准化净分差 | 95% CI 下界 > `-0.10 SD` |
| 极端失败保护 | 花猪率、未听牌率相对基准恶化均不超过 2 个百分点，或 CI 未证明恶化 |
| 人数一致性 | 2/3/4 人均通过，不允许合并抵消 |

该门禁只证明没有为人类化显著牺牲强度，不证明达到真人高手水平。

## 9. G5 真人行为相似度（有数据才可验收）

真人数据须合法取得、去标识化，并保留规则、人数、合法动作集和决策时点。train/dev/test 按玩家 ID 隔离。

| 类型 | 指标 | 通过标准 |
|---|---|---|
| 主指标 | 按上下文分层的动作分布 JSD | 加权 JSD ≤0.15；人数、局阶段、定缺、响应/自摸等核心层均 ≤0.20 |
| 主指标 | 真人动作 NLL 相对 RuleAI 改善 | ≥5%，配对 95% CI 下界 >0 |
| 辅助 | Top-1 动作一致率 | 分层报告，不单独作门槛 |
| 辅助 | 碰/杠/胡/过 Brier score | 不劣于 RuleAI，至少 3 类中的 2 类显著改善 |
| 辅助 | 思考时长 Wasserstein 距离 | 相对 RuleAI 改善 ≥10%；仅在时间戳可信时启用 |

数据未覆盖的房规或水平必须从结论范围排除。“真人相似”只表示上述统计维度接近，不等于通过图灵测试或主观体验优秀。G5 阈值在取得合规数据并完成盲测基线后须复核批准。

## 10. G6 局间学习效果（条件门禁）

仅在产品声明实现 RP-033 或等价能力时启用。

| 指标 | 通过标准 |
|---|---|
| 对手动作 Brier score | 相对关闭学习改善 ≥5%，95% CI 下界 >0 |
| 每局净分 | 标准化差值 95% CI 下界 >-0.10 SD |
| 冷启动保护 | 前 10 局 G1 全通过，净分恶化不超过 0.10 SD |
| 边界 | 隐藏信息读取 0；只保存批准字段；跨 game_id 行为 100% 符合规格 |
| 复现 | 相同版本、配置、seed、序列产生一致模型状态哈希和动作序列 |

## 11. G7 复现、性能与审计（硬门禁）

| 指标 | 通过标准 |
|---|---|
| 确定性复现 | 相同 PlayerView、配置、seed 的动作/trace 哈希一致率 100% |
| 单次决策延迟 | 标准评测机 p95 ≤25 ms；同时报告 p50/p95/p99 |
| 四人批跑成本 | 相对 RuleAI wall time ≤3.5× |
| 观测与 mask | p95 ≤5 ms，且相对 v1 环境 ≤1.5× |
| 审计完整率 | 必填字段完整且哈希链有效 =100% |

记录硬件、OS、Python 和冷/热启动口径；Windows、macOS 至少各执行一次 G1、G2、G7 平台验收。

## 12. 防投机与证据要求

- JSD、macro-F1 或净分不能抵消硬规则失败；不得使用未来牌、暗牌或 oracle；
- 排除条件必须预注册；缺失、无效、超时不得静默丢弃；
- 多指标/子群尝试使用 Holm 校正并保留全部记录；
- 正式产物含评测配置、版本、seed manifest、追踪矩阵、G1–G7 分层结果、失败重放 ID 和 Markdown 报告；
- 使用真人数据时增加数据卡、授权范围和隔离证明，不落盘身份信息或未脱敏牌谱；
- 建议路径：`configs/evaluation/`、`tests/spec_trace/`、`artifacts/evaluation/`、`docs/status/`。
