## 2. 强制规则

| 规则 ID | 规则 |
|---|---|
| RULE-001 | 不修改两份锁定文档。 |
| RULE-002 | 当前阶段不修改程序代码，除非具体任务明确授权。 |
| RULE-003 | 不把类、接口、占位函数或测试名称视为实现证据。 |
| RULE-004 | 所有结论必须提供文件路径、符号名称、测试名称或运行证据。 |
| RULE-005 | 未找到证据时必须明确写“未找到”，不得推测已实现。 |
| RULE-006 | 确定性规则、确定性算法、人类化启发式和可训练模型必须分开描述、审计和判定。 |
| RULE-007 | 新文档中的每项功能必须使用稳定单元 ID。 |
| RULE-008 | 所有文档使用 UTF-8 Markdown。 |

## 3. 证据判定要求

实现结论必须至少关联下列一种可核查证据：

- 文件路径及具体符号名称；
- 能证明行为的测试名称及其断言；
- 实际运行命令及结果；
- 可复核的审计或验收产物路径。

仅发现类名、接口声明、占位函数或测试名称时，不得据此判定功能已经实现。没有找到满足要求的证据时，结论统一记录为“未找到”。

## 4. 方法分类

所有规格单元和审计结论必须明确归入以下一种类型，不得混写或相互替代：

| 类型 | 定义边界 |
|---|---|
| 确定性规则 | 由成都麻将房规或产品规则直接规定的权威行为。 |
| 确定性算法 | 在相同输入和版本下产生相同结果的工程算法。 |
| 人类化启发式 | 模拟有限认知、风格或行为习惯的人工设计策略。 |
| 可训练模型 | 参数能够通过训练数据或优化过程学习的模型。 |

## 5. 变更规则

本规则文档的任何修改均须由用户明确授权，并在 `docs/changelog.md` 和 `docs/status/LATEST.md` 中记录。修改本文件不构成修改两份锁定来源的授权，也不构成修改程序代码的授权。
