# F0031 / F0032 量化能力审查

> 日期：2026-07-29  
> 审查对象：`docs/features/F0031_humanlike_quantitative_acceptance.md`、`docs/features/F0032_humanlike_evaluation_dataset.md`  
> 目标：判断两份 Draft 是否足以对既有审计报告的 96 个功能单位作准确量化评价  
> 结论等级：**Needs revision**

## 1. 结论

**目前不能对 96 个评估单位作准确、逐项、可复现的量化评价。**

F0031 已建立合理的七组门禁和五级结论；F0032 已规划决策粒度、数据隔离、切分和质量门禁。两者共同解决了“用什么类型的证据评价”的框架问题，但尚未解决以下三个落地问题：

1. 审计中的 96 行没有稳定的 `AU-001～AU-096` 唯一 ID，也不是全部原子化要求；
2. 没有 `评估单位 → 指标公式 → 数据字段 → 样本/场景 → 阈值 → 证据文件` 的逐项映射；
3. schema、验证器、golden cases、模拟数据和真人数据都尚未实现，当前只有规划，没有可计算分子/分母。

因此当前能力应表述为：

| 问题 | 当前答案 |
|---|---|
| 能否把 96 单位全部登记并统计覆盖率？ | **设计上可以**，需先原子化和编号 |
| 能否对规则/接口单位给出 binary pass/fail？ | **部分可以**，需实现逐项 golden case |
| 能否给每个单位输出准确效果分数？ | **不可以**；并非所有工程单位都适合效果分数 |
| 能否给整体“人类化完成百分比”？ | **不建议**，会把安全、语义、强度和真人相似错误相加 |
| 能否现在重新计算 96 单位完成度？ | **不可以**，没有已执行数据和冻结追踪矩阵 |

## 2. F0031 准确性审查

### 2.1 正确且应保留的设计

- 把机制可信、行为可辨识、策略强度、真人相似和学习效果分开，避免单一总分；
- G1 的非法动作、信息泄漏、守恒等使用零容忍硬门禁；
- G2 要求条款、实现、测试、结果追踪，是覆盖 96 单位的正确入口；
- 配对 seed、座位轮换、2/3/4 人分层和 bootstrap CI 适合对局比较；
- 无真人数据时 G5 为 Not Evaluated，结论边界准确；
- 把统计显著性与实质效应分离，方法方向正确。

### 2.2 阻断准确量化的问题

| 严重度 | 问题 | 影响 | 必要修订 |
|---|---|---|---|
| Critical | G2 只要求未来建立条款矩阵，当前没有 96 单位映射 | 无法证明任一 gate 覆盖了哪一审计单位 | 建立 AU-001～AU-096 crosswalk；复合行拆为子断言 |
| High | “关键条款”没有定义，非关键允许 95% 覆盖 | 可通过重新分类规避难测要求 | 每个 AU 指定 criticality；96 个单位登记和状态必须 100%，只有批准的不可测子断言可 N/A |
| High | G3 对所有参数统一使用方向一致率、Cliff's delta 和 macro-F1 | 某些参数是枚举/机制，不具备相同效应形态；分类类别数未定义 | 每个行为声明单独定义 treatment、control、主指标、方向、最小效应和分类标签 |
| High | G4 的 `-0.10 SD` 未冻结 SD 来源和估计方法 | 更换基准批次可改变非劣界值 | 用冻结基准集估计 pooled SD；定义 paired estimator、座位聚合和异常局处理 |
| High | G5 JSD 未定义上下文桶、权重、平滑和最小桶样本；NLL 假设策略输出概率 | 不同实现可算出不同结果；确定性策略无法直接算 NLL | 冻结 context taxonomy、权重、零概率平滑；定义从评分到概率的校准层或取消 NLL 门禁 |
| High | 固定最低样本与“CI 门槛带宽”并存，但门槛带宽未定义 | 无法执行扩样规则 | 为每个主指标定义最大 CI 宽度或预先完成功效分析 |
| Medium | G6 “每个对手条件”和状态持久化范围未定义 | 学习效果样本不可复现 | 冻结 opponent suite、序列长度、冷启动窗口和持久化字段 |
| Medium | G7 “标准评测机”未给硬件基线；macOS/Windows 仅说各一次 | 性能和跨平台结果不可比较 | 指定机器档案、进程模式、预热、重复次数和平台最低样本 |

### 2.3 阈值可信度

| 门禁 | 当前量化程度 | 阈值可信度 |
|---|---|---|
| G1 安全合法 | 高 | 高；零容忍与规则性质一致 |
| G2 语义覆盖 | 中 | 覆盖率明确，但单位和关键性未冻结 |
| G3 风格辨识 | 中 | 有数字，但属首版工程假设，缺当前基线 |
| G4 强度非劣 | 中 | 方法合理，margin 和 SD 口径待校准 |
| G5 真人相似 | 中低 | 有候选阈值，无真人基线、分层和概率输出契约 |
| G6 学习效果 | 中低 | RP-033 未实现，对手套件未定义 |
| G7 复现性能 | 高 | 沿用既有门禁，但环境定义需补齐 |

结论：F0031 对工程硬门禁较准确，对行为/真人效果是“可执行方向 + 暂定阈值”，尚不是校准完成的验收标准。

## 3. F0032 准确性审查

### 3.1 正确且应保留的设计

- 决策级 grain 与动作相似度指标一致；
- `policy_view / action_label / evaluation_truth` 物理隔离能防止事后真值泄漏；
- 玩家、牌局、session 和近重复组不得跨 split，能够抑制常见评估泄漏；
- action 必须属于 legal set、ruleset 必须可识别、Critical 失败阻断发布，质量门禁合理；
- 真人正式测试集永不训练，Pilot 与冻结 Eval 分离，边界准确；
- P1 只作最低探索规模、P2 最终依功效分析确定，避免把行数当充分条件。

### 3.2 阻断准确量化的问题

| 严重度 | 问题 | 影响 | 必要修订 |
|---|---|---|---|
| Critical | 尚无机器可读 schema、验证器和任何已验证 release | 目前无法计算质量、覆盖或 G5 指标 | 先实施 F0032-1/2，并发布 P0 合成夹具 |
| Critical | 尚无已授权真人来源 | 不能验证 G5，也不能校准 JSD/NLL/Brier 阈值 | 完成来源授权、Data Card 和 P1；否则保持 Not Evaluated |
| High | 外部牌谱能否还原“当时完整合法动作集”未验证 | 动作标签可能合法，但候选分母错误，NLL/Brier 失真 | 每个来源做 response-window reconstruction audit；不可还原的指标禁用 |
| High | 覆盖维度已列出，但每个核心层的最小有效样本未量化 | 100,000 常见 discard 可掩盖稀有杠/抢杠/过胡缺失 | 建立 strata quota 表并为 AU/动作类型设置最低样本 |
| High | 玩家水平和真人/机器人/托管身份依赖来源标签 | 样本混杂会使“真人相似”失真 | 定义 eligibility 和排除规则，报告 unknown 比例并做敏感性分析 |
| Medium | 来源集中度 >60% 只触发审查，没有最大外推边界 | 平台风格可能被误称为普遍真人风格 | 对外结论绑定来源/水平/房规；增加跨来源验证目标 |
| Medium | JSONL 权威但嵌套 PlayerView 的规范化和浮点/枚举 canonicalization 未定义 | 内容哈希、去重和跨平台重放可能不稳定 | 冻结 canonical JSON 规则、排序、编码和 hash 算法 |

结论：F0032 的治理和防泄漏规划较准确，但它是数据产品设计，不是现成数据源；在 P0/P1 之前不能为 96 单位提供实测证据。

## 4. 96 个评估单位的可量化性

### 4.1 正确的评价模型

96 个单位不应都强制使用同一种连续分数。每个原子断言应选择以下证据类型：

| 类型 | 适用要求 | 推荐输出 |
|---|---|---|
| INV 不变量 | 合法性、守恒、信息边界、哈希、配置拒绝 | pass/fail、失败次数、样本数 |
| SEM 语义 | 换牌、定缺、响应、计分、状态转移 | golden cases 通过数/总数、分支覆盖 |
| BEH 行为 | 风格、认知、计划、风险、节奏 | 效应值、CI、方向一致率、分层指标 |
| STR 强度 | 净分、花猪、未听牌、番数 | paired delta、非劣 CI |
| HUM 真人相似 | 真人条件动作和节奏 | JSD/NLL/Brier/距离及 CI |
| LRN 学习 | RP-033、对手画像更新 | 预测改善、收益非劣、复现 |
| DOC/ARCH | 版本绑定、模块边界、可插拔接口 | contract test + 追踪证据，不制造伪效果分数 |

一个审计单位可能含多个类型，必须拆为原子断言。例如“规则读取并形成风格”至少拆为配置读取正确性（INV/SEM）和风格产生效果（BEH），不能用一个 pass 覆盖两者。

### 4.2 当前覆盖成熟度

| 能力层 | 对 96 单位的当前状态 |
|---|---|
| 单位登记 | 审计报告有 96 行，但无稳定 ID/机器可读清单 |
| 单位原子化 | 未完成；多行包含多个功能与效果断言 |
| 单位到 gate 映射 | 未完成 |
| 单位到指标/公式映射 | 未完成 |
| 单位到数据字段/子集映射 | 未完成 |
| 单位到阈值映射 | 只有 gate 级通用阈值，未逐单位冻结 |
| 自动计算 | 未实现 |
| 实测数据 | 现有工程测试可复用；F0032 数据 release 为 0，真人 release 为 0 |

所以，“96/96 均有某种未来评估路径”可以通过补充设计实现；“96/96 当前已经能准确量化”不成立。

## 5. 必须新增的 96×量化追踪矩阵

建议新增机器可读 `evaluation_units.yaml`，每个原子单位至少包含：

```yaml
- unit_id: AU-001
  source_document: humanlike_rules_v1
  source_clause: "0.x"
  requirement: "..."
  assertion_id: AU-001-A
  evidence_type: INV
  gate: G1
  criticality: hard
  metric_id: illegal_action_rate
  formula: illegal_actions / total_actions
  dataset: DS-Sim
  strata: [player_count, ruleset]
  minimum_sample: "2/3/4 each 200 games"
  threshold: "== 0"
  implementation_anchor: "engine/legal.py"
  test_anchor: "tests/..."
  status: planned
  result_artifact: null
```

矩阵质量门禁：

- 96 个原审计单位登记率 100%；
- 拆分后的所有原子断言均有 evidence type、gate、metric、dataset、threshold 和 owner；
- 每个原子断言只能为 Passed / Failed / Not Evaluated / N/A-with-approval；
- hard requirement 不允许 N/A；
- 单位结论按最弱原子断言决定，不做平均；
- 总览只报告各状态计数和分类型覆盖，不输出误导性的单一完成百分比。

## 6. 修订后何时可以准确评价

| 里程碑 | 可形成的结论 |
|---|---|
| Q0：96 单位编号、原子化、crosswalk 评审通过 | 能证明量化设计覆盖 96/96 |
| Q1：F0032 P0 + golden/contract tests | 能准确评价 INV/SEM/DOC/ARCH 类单位 |
| Q2：DS-Sim + G3/G4 基线校准 | 能评价 BEH/STR 类单位 |
| Q3：已授权 P1 + G5 指标复核 | 能探索评价 HUM 类单位，仍需冻结测试集 |
| Q4：DS-Human-Eval v1 冻结并盲测 | 能在限定人群/房规范围内正式评价 HUM 类单位 |
| Q5：RP-033 实现和对手套件冻结 | 能评价 LRN 类单位 |

只有到 Q5，且没有未覆盖原子断言时，才可以说“96 个原审计单位都获得了准确的量化或明确的 Not Evaluated/N/A 结论”。这仍不等于 96 个单位全部通过。

## 7. 最小修订建议

1. 新增 F0031 附录 A：metric registry，冻结公式、单位、分母、阈值依据和 CI 宽度；
2. 新增 F0031 附录 B：AU-001～AU-096 crosswalk，并把复合行拆成原子断言；
3. 新增 F0032 strata quota，按动作类型、人数、房规和关键 AU 设最低有效样本；
4. 决定确定性策略是否提供经批准的概率校准层；否则删除 G5 NLL/Brier 的强制门槛；
5. 先用 P0/DS-Sim 计算工程基线，再审批 G3/G4 阈值；
6. 真人来源未获授权前不审批任何“真人相似已达标”的结论。

## 8. 最终评价

| 维度 | 评价 |
|---|---|
| 方法论方向 | 正确 |
| 工程硬门禁量化 | 较充分 |
| 行为效果量化 | 有框架，未校准 |
| 真人效果量化 | 有设计，无数据、无可执行概率契约 |
| 96 单位逐项追踪 | 缺失 |
| 当前是否可实施部分评估 | 可以，优先 INV/SEM/DOC/ARCH |
| 当前是否可准确量化全部 96 单位 | **不可以** |
